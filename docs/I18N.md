# Контракт локализации RU / EN / UZ

Актуально на: 2026-08-09

Поддерживаемые локали: `ru`, `en`, `uz`

Default / `x-default`: `ru`

## 1. Что означает «полная локаль»

Локализация является частью сборочного контракта, а не необязательным
переводом после релиза. Для каждой из трёх локалей обязательны:

- вся информационная архитектура главной страницы;
- 26 project card с одинаковым порядком, route и набором полей;
- identity каждого продукта: `name` и `descriptor`;
- 19 case pages с полным содержанием и общим UI;
- локализованные case metadata до выполнения JavaScript;
- сохранение выбранного языка, главы case и deep-link контекста.

Ни одна locale не может иметь сокращённую структуру относительно RU.
`scripts/validate-site.js` сравнивает shape объектов, обязательные поля и
порядок, поэтому «пустой перевод с рабочим fallback» не считается готовой
локалью.

## 2. Источники истины

| Слой | Source | Контракт |
|---|---|---|
| Product identity | `src/content/product-registry.js` | 25 × `ru/en/uz`: `name`, `descriptor` |
| Главная и карточки | `src/content/content.js` | одинаковая полная структура `CONTENT.ru/en/uz`; 26 карточек в `featuredRank` order |
| Case content | `src/projects/landings-data.js` | 16 × 3 locale; одинаковые обязательные поля |
| Case UI | `LP_UI` в `src/projects/render.js` | labels, CTA, главы и служебный текст во всех locale |
| Static metadata/body | `build.js` + `LP_render()` | 48 локализованных HTML без расхождения source/generated |
| Runtime routing | `src/projects/landing.js` и main app | переключение locale с сохранением route/hash |

Обязательная структура каждого case-текста:

```text
tag
role
signal
quick[3].v
what
problem
architecture
why
unique
employer
quality
boundary
```

`boundary` переводится полностью и сохраняет смысловые ограничения. Нельзя
смягчать NDA, medical/financial disclaimer, discovery status или
`SOURCE_INCOMPLETE` в одной из локалей.

## 3. URL-модель

### Главная

Главная остаётся одним статическим документом с runtime-localized body:

| Locale | Shareable URL |
|---|---|
| RU | `/CV-Samandar/` |
| EN | `/CV-Samandar/?lang=en` |
| UZ | `/CV-Samandar/?lang=uz` |

Для RU параметр `lang` удаляется. При переключении языка app обновляет query
через History API и сохраняет существующий `#section` или `#proj-<slug>`.
Прямая загрузка `?lang=en#projects`, переключение на UZ и reload обязаны
восстановить тот же язык и раздел.

Главная имеет один общий static `<head>` с identity metadata и alternate links.
Её body локализуется в runtime; это **не** три отдельно prerendered metadata
страницы. Нельзя описывать main head как три локализованных HTML.

### Case pages

Каждый case имеет отдельный статический URL на язык:

| Locale | Route template | Относительный asset/base path |
|---|---|---|
| RU | `/CV-Samandar/projects/<slug>/` | `../../` |
| EN | `/CV-Samandar/projects/<slug>/en/` | `../../../` |
| UZ | `/CV-Samandar/projects/<slug>/uz/` | `../../../` |

Итого: 19 products × 3 locale = **57 generated landing HTML**.

Переключатель case-языка делает полноценную навигацию на canonical locale
route. Legacy/explicit `?lang=` распознаётся только для допустимых `ru/en/uz`,
после чего query удаляется в пользу route. Текущий hash главы сохраняется.

## 4. Локализованные metadata case pages

Каждый из 57 generated HTML содержит locale-specific данные до JavaScript:

- `<html lang="ru|en|uz">` и `data-lp-lang`;
- `<title>` из product name + локализованного `tag`;
- `<meta name="description">` из локализованного `signal`;
- self-referential canonical на текущий locale route;
- полный набор `hreflang=ru|en|uz|x-default`, где `x-default` ведёт на RU;
- `og:title`, `og:description`, `og:url`, `og:locale` и alternate locale;
- абсолютные `og:image` и `twitter:image` на product artwork 1536×512;
- JSON-LD `CreativeWork` с локализованными `description`, `url` и
  `inLanguage`;
- локализованный body, совпадающий с `LP_render(product, locale, base)`.

Canonical каждой locale страницы ссылается на саму себя. RU, EN и UZ не
canonicalize друг друга: связь задаётся `hreflang`, а не подменой canonical.
Sitemap перечисляет все 57 locale route плюс главную — **58 URL**.

## 5. Сохранение контекста чтения

Case page имеет пять стабильных chapter id:

```text
thesis → context → system → evidence → boundary
```

Scroll spy обновляет текущую главу и URL hash. При смене RU/EN/UZ сохраняется
актуальная глава, включая direct deep link и reload. Например:

```text
/projects/chat-app/#system
→ /projects/chat-app/en/#system
→ /projects/chat-app/uz/#system
```

Возврат на главную всегда включает product context:

```text
RU:    ../../#proj-<slug>
EN/UZ: ../../../#proj-<slug>
```

Главная раскрывает каталог, если карточка находилась за «Все проекты»,
пропускает intro для deep link и помещает точную карточку в видимую область.

## 6. Fallback и допустимые значения

- Допустимы только `ru`, `en`, `uz`; неизвестное значение не становится locale.
- RU является authoring/default fallback внутри renderer, но validator требует
  полную locale parity, поэтому fallback не заменяет готовый перевод.
- Static route locale является главным источником языка case page.
- `sm-lp-lang` записывает последнее действие переключателя для совместимости,
  но текущий runtime не читает его для переопределения static route: явный
  canonical URL остаётся единственным источником case-языка.
- Если JavaScript недоступен, generated case уже содержит правильный язык,
  metadata, body, navigation links и CTA.
- Все authored locale-файлы должны быть NFC-normalized, без mojibake и
  смешанных Latin/Cyrillic токенов, выявляемых validator.
- Runtime не выполняет машинный перевод и не модифицирует продуктовые факты.

## 7. Правила редакторского изменения

Любая смена названия, статуса, claim, CTA или архитектурного смысла делается
сразу в RU/EN/UZ. При редактировании нужно проверить:

1. одинаковую структуру и число элементов;
2. сохранение maturity, confidentiality и privacy boundary;
3. отсутствие нового claim без evidence;
4. локализованное название без изменения canonical `id`/`slug`;
5. корректность длинных EN/UZ строк на mobile и при 200% text zoom;
6. canonical, hreflang, OG/Twitter и JSON-LD после build;
7. переключение locale с `#chapter` и возврат к `#proj-<slug>`;
8. `npm run validate` после генерации.

Готовность локали доказывается source parity, generated HTML и browser tests,
а не только визуальным наличием переключателя RU/EN/UZ.
