# Art direction V8.1 — Release Field

Статус: локальный release candidate в ветке
`codex/layout-projects-seo-pricing`; production release этой итерации ещё не
заявлен.

Область: главная, 25 карточек продуктов, 16 case routes и три полные локали.

Этот документ фиксирует художественный и инженерный контракт текущей версии.
Он не утверждает получение Awwwards-награды и не заменяет visual,
performance, physical-device или assistive-technology proof.

## 1. Главная идея

Сайт — единое поле выпуска продукта, а не коллекция «технологичных» эффектов.
Один маршрут проходит через все сцены:

`BUILD → VERIFY → SHIP`

Builder отвечает за целостный результат, QA — за проверяемость решения.
Характер создают масштаб, физический материал, точная сетка, свет и пауза.
Неон, случайные HUD-виджеты, псевдотелеметрия и отдельная цветная вселенная
для каждой секции запрещены.

Stones используется как ориентир принципа, а не как шаблон: один материальный
мир, одна акцентная линия, крупная типографика и движение, которое продолжает
содержание. Портфолио сохраняет собственную тему выпуска и проверки продукта.

## 2. Первые пять секунд

Hero сразу отвечает на три вопроса:

1. Результат: «Из задачи — в продукт».
2. Ответственность: Samandar Mansurkhodjaev / Product Engineer.
3. Метод качества: Build, Verify, Ship.

Signature object — `Release Specimen`: три обработанных физических слоя,
собранные одной измерительной осью. Это не диаграмма процесса и не интерфейс
машины; объект материализует один продукт, прошедший три контрольных состояния.
Один inspection-light проходит объект и заканчивается в спокойной читаемой
позе.

Release Specimen реализован code-native HTML/CSS и существует в трёх
согласованных состояниях: parser frame-zero, Intro и React Hero. Нет raster
readiness gate, layout shift или отдельной декоративной сцены для каждого
этапа загрузки.

Заголовок состоит из двух цельных Oswald phrase spans. Посимвольная анимация,
italic-output и независимый font fitting запрещены: они создавали смещение
baseline и визуальный разнобой. На deep link и при возврате из кейса Intro
обходится, а Hero сразу получает финальную позу без промежуточной маски.

Первый Intro сохраняет окно примерно 2.4–2.85 секунды; повторный — примерно
1.95–2.4 секунды. Это readiness gate для shell, локальных шрифтов и Hero, а не
декоративная задержка. Parser-frame сразу блокирует `#root` семантически;
release снимает `inert`, `aria-hidden`, scroll lock и overlay идемпотентно.

Portrait mobile использует самостоятельную композицию: specimen, тезис, CTA,
Proof Rail и видимый handoff в Signal. Phone landscape и compact desktop имеют
свои правила; desktop-параллакс не переносится на touch механически.

## 3. Навигация и курсор

Desktop rail оставляет только brand, текущую главу, одно contact-действие и
Index trigger. Языки доступны внутри Index и не конкурируют с первым экраном.
Mobile rail показывает brand, реальную главу и крупный 44×44+ trigger.

Fullscreen Index раскрывает все 12 глав в фактическом DOM-порядке. Это
модальный слой с focus trap, inert внешней оболочкой, Escape, возвратом фокуса
и читаемой resting composition ещё до hover. Фоновая геометрия сведена к общей
сетке и одному datum; декоративные кольца и цветные preview-миры удалены.

Desktop-cursor — sampling reticle. В покое это точка и тихое кольцо; только над
действием он становится измерительной рамкой и показывает глагол. Старый стек
из crosshair, QA-jaws, координат, ring и label удалён. Touch никогда не
имитирует cursor. Реализация использует общий pointer stream.

## 4. Двенадцать сцен

Все главы принадлежат одному тёмному Release Field. Отличается композиция и
смысловой жест, но не визуальная вселенная.

| № | Сцена | Композиция | UX-роль |
|---:|---|---|---|
| 01 | Hero | Release Specimen и proposition plane | позиционирование и первое действие |
| 02 | Signal | диагностические строки с ручным disclosure | причины работать вместе |
| 03 | About | README / рабочая записка | проверяемый профиль |
| 04 | Projects | предметный каталог и mobile filmstrip | сильнейшие продукты и полный каталог |
| 05 | Builder | scope console и собранный brief | превратить запрос в конфигурацию |
| 06 | Skills | stack matrix и QA layer | показать реальный стек |
| 07 | Services | operating modes | объяснить форматы сотрудничества |
| 08 | CV | тёмный chapter shell и светлый документ внутри | читаемое резюме и выгрузки |
| 09 | Process | delivery line | объяснить путь до release |
| 10 | FAQ | явное раскрытие ответов | снять возражения |
| 11 | Trust | тёмный chapter shell и светлый protocol внутри | показать QA-гарантии и границы |
| 12 | Contact | тёплая dispatch-плоскость | собрать brief и дать следующий шаг |

CV и Trust не являются белыми полноэкранными разрывами. Светлая поверхность
принадлежит документу внутри тёмной главы и использует отдельные ink tokens.

## 5. Projects и изображения

Каталог содержит 25 канонических продуктов без дублей. Первые четыре видны
сразу; остальные раскрываются явным действием «Все проекты». Desktop использует
управляемый feature-ритм, mobile — горизонтальную snap-галерею с честным
pager и видимым продолжением.

Каждая обложка — самостоятельная предметная фотография 1536×512 WebP с
responsive 768/1152 derivatives, центральной safe zone 84%, без текста,
логотипа, UI и закрытых данных. Уникальность строится на объекте, материале,
свете и registry accent. Каркас карточки остаётся общим.

Live-продукт открывает сайт основным CTA, GitHub — отдельным вторичным. Case
открывает внутреннюю визитку и возвращает к исходной `#proj-<slug>` карточке
без повторного Intro.

## 6. Case routes

Все 16 case routes теперь используют общий Release Field: Oswald для display,
Inter для чтения, JetBrains Mono для доказательной метаинформации, одну сетку,
прямоугольные controls и одинаковый chapter rhythm. Старые декоративные wave,
gauge, lens, ring и pseudo-HUD signatures отключены.

Индивидуальность сохраняют фотография, accent, тезис, архитектурная схема,
QA-блок и аргументация. Первый mobile viewport показывает название, смысл,
обе CTA и предметный объект. Порядок неизменен: задача → роль → архитектурный
принцип → стек → QA-подход → публичная граница → CTA. RU, EN и UZ равноправны.

## 7. Motion grammar

- Нативный scroll остаётся единственным владельцем перемещения страницы.
- Pointer/scroll/resize эффекты подписываются на общий runtime.
- Один transform имеет одного visual owner.
- Section entrance использует общий release rhythm, а направление зависит от
  композиции главы; финальная поза всегда полностью читаема.
- Между главами работает один datum/seam, а не новый декоративный мир.
- Кнопка получает короткий inspection sweep только при реальном hover/focus.
- Medium/low tier сохраняет смысловой жест без бесконечного RAF.
- Reduced motion убирает пространственное движение, но не смысл и контраст.
- WebGL остаётся enhancement с доступным fallback.

## 8. Пять проходов приёмки

1. Факты: нет выдуманных метрик, клиентов, отзывов и production claims.
2. UX: понятны тезис, действие, affordance, возврат и состояние.
3. Art direction: приём связан с содержанием и остаётся частью Release Field.
4. Engineering: доступны locale parity, recovery, tier и fallback.
5. Regression: desktop/mobile/landscape/zoom/keyboard/reduced/deep-link.

Скриншот не доказывает плавность, synthetic test не заменяет physical
iPhone/Android или NVDA/VoiceOver/TalkBack sign-off.

## 9. Release evidence

Минимальный candidate проходит:

```text
npm run validate
npm run check:build
npm run scan:secrets
npm audit --audit-level=high
npm test
npm run test:performance
npm run qa:visual
git diff --check
```

После deploy обязательны `npm run test:production` и `npm run check:live`.
Локальный PASS не является production proof.
