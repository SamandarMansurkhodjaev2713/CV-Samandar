Контекст

Что это

Приватная proctoring/monitoring-система: Windows client-agent, backend ingestion API и admin-панель для просмотра событий, статусов и материалов проверки.

Какую проблему решает

Proctoring не может быть просто веб-формой. Нужны устанавливаемый клиент, heartbeat, сбор событий, защищённая передача, retry-логика, политика мониторинга, admin-видимость и понятный workflow проверки.

Система

Технический стек

C#Node.jsExpressPrismaPostgreSQLReact

Архитектура

Windows-agent собирает события и отправляет telemetry/uploads в backend; API валидирует и сохраняет данные; admin-панель даёт операторам обзор статусов, нарушений и истории; deployment-слой упрощает установку и обновление.

Почему именно так

Proctoring живёт на границе desktop, backend и операционного контроля. Разделение agent, ingestion API и admin-панели делает систему устойчивее, наблюдаемее и безопаснее.

Доказательства

Сильные стороны

Проект показывает работу за пределами обычного web: поведение client-agent, Windows-deployment, sensitive-телеметрия, retries, admin-workflow и security-first мышление.

Что это доказывает

Умение строить системные продукты с desktop-частью, backend-пайплайном, безопасной передачей данных и административным интерфейсом.

Quality · QA

Как обеспечивалось качество

xUnit/Moq integration-проверки сохранения и загрузки политик, генерации отчёта, изолированной работы с файлами и передачи результата в transmission-сервис. Изоляция файловой системы и mocked-transport выбраны, чтобы надёжно тестировать observable behavior без реального сервера и пользовательских данных.
