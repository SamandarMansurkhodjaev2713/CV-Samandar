Context

What it is

A private proctoring/monitoring system: a Windows client-agent, a backend ingestion API and an admin panel to review events, statuses and check materials.

The problem it solves

Proctoring can't be a web form. It needs an installable client, heartbeat, event collection, protected transport, retry logic, a monitoring policy, admin visibility and a clear review workflow.

03 / 05

System

Technical stack

C#Node.jsExpressPrismaPostgreSQLReact

Architecture

A Windows agent collects events and sends telemetry/uploads to the backend; the API validates and stores the data; an admin panel gives operators a view of statuses, violations and history; a deployment layer simplifies install and update.

Why this architecture

Proctoring lives at the border of desktop, backend and operational control. Separating the agent, the ingestion API and the admin panel makes the system more robust, observable and secure.

QA · evidence

How quality was engineered

xUnit/Moq integration checks for saving and loading policies, report generation, isolated file handling and passing the result to a transmission service. File-system isolation and mocked transport were chosen to test observable behavior reliably without a real server or user data.

Boundaries

Honest boundaries

The system gathers evidence for a human decision rather than issuing an automatic verdict: completeness of violation detection is not claimed. Legal grounds, notice and participant consent are the customer's responsibility. The client targets Windows; macOS, Linux and mobile platforms are out of scope.
