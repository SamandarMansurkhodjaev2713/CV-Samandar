02 / 05

Context

What it is

A private offline desktop app for medical/research calculations, patient profiles and local work with sensitive calculation logic.

The problem it solves

In health-tech and research tools you can't rely on “roughly works”. Deterministic calculations, reproducibility, privacy, an offline mode and a clean split of UI from domain logic all matter.

03 / 05

System

Technical stack

RustTauriReactTypeScriptSQLite

Architecture

The Tauri shell provides the desktop runtime, a React UI handles forms and flows, a Rust core holds calculation logic and domain rules, SQLite provides local storage, and typed IPC holds the boundary between UI and core.

Why this architecture

Sensitive calculation logic must be separated from the interface. It simplifies testing, reduces the risk of accidental UI errors and makes the app suitable for offline-first use.

Quality · QA

How quality was engineered

React/Vitest checks for forms, the calculation workspace, localization and reports, plus a Rust/SQLite integration test for result reproducibility. For a medical calculation product the key criterion is the same result for the same input and a transparent formula.

Boundaries

!
Honest boundaries

This is a calculation tool for a specialist, not a certified medical device: the product has not gone through regulatory certification and is not intended for diagnosis. Responsibility for the clinical decision stays with the physician. It runs locally and offline — cross-device sync and cloud storage are out of scope.
