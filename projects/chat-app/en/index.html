02 / 05

Context

What it is

ChAT is a public React Native messenger prototype designed around unstable networks: a durable local outbox, duplicate-safe redelivery, realtime synchronization and verifiable Firebase access rules.

The problem it solves

A happy-path chat looks simple until connectivity disappears between tapping send and server acknowledgement. A message can vanish, duplicate or remain in a false state, while weak security rules may expose another user's data.

03 / 05

System

Technical stack

React NativeExpoTypeScriptFirebaseSQLiteJest

Architecture

Feature modules isolate domain logic and adapters. SQLite stores a durable outbox, each message owns a stable idempotency key, a sync worker applies bounded backoff, and Firebase services provide auth, realtime, media and server-side OTP. ESLint prevents architectural boundary bypasses.

Why this architecture

Local-first state keeps the UI honest: pending, failed and delivered are real states, not optimistic decoration. Idempotency separates redelivery from recreation, and security rules run in the emulator before any production backend.

Evidence

Strengths

Message reliability is treated as a protocol, not a spinner. An offline outbox, server verification and lint-enforced boundaries provide verifiable guarantees before production infrastructure exists.

What it proves

The case demonstrates mobile systems thinking: local persistence, distributed state, security, serverless backend, architecture contracts and honest management of unfinished work.

Quality · QA

How quality was engineered

The repository documents 171 client tests, 28 Functions tests and 35 emulator security-rule checks covering outbox, retries, idempotency, OTP, rate limiting and access. It also states that a physical-device pass and production backend are not yet complete.
