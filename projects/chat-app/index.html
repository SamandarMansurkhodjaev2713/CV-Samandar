Контекст

Что это

ChAT — публичный React Native прототип мессенджера, спроектированный вокруг нестабильной сети: локальная outbox-очередь, повторная доставка без дублей, realtime-синхронизация и проверяемые Firebase access rules.

Какую проблему решает

Happy-path чат выглядит простым, пока соединение не пропадает между нажатием «отправить» и подтверждением сервера. Тогда сообщение может исчезнуть, появиться дважды или остаться в ложном статусе, а слабые security rules откроют чужие данные.

Система

Архитектура

Feature-модули изолируют domain и adapters. SQLite хранит durable outbox, каждое сообщение имеет стабильный idempotency key, sync worker применяет bounded backoff, а Firebase services отвечают за auth, realtime, media и server-side OTP. ESLint запрещает обход архитектурных границ.

Почему именно так

Local-first state делает UI честным: pending, failed и delivered — реальные состояния, а не optimistic decoration. Idempotency отделяет повторную доставку от повторного создания, security rules тестируются в emulator до подключения production backend.

04 / 05

Доказательства

Сильные стороны

Надёжность сообщения рассматривается как протокол, а не как spinner. Offline outbox, server verification и lint-enforced boundaries дают проверяемые гарантии ещё до появления production-инфраструктуры.

Что это доказывает

Кейс показывает mobile systems thinking: локальное хранилище, распределённое состояние, безопасность, serverless backend, архитектурные контракты и честное управление незавершённостью.

Quality · QA

Как обеспечивалось качество

171 client test, 28 Functions tests и 35 emulator security-rule checks покрывают outbox, retry, idempotency, OTP, rate limit и права доступа. Документация честно фиксирует непроведённый physical-device pass и отсутствие production backend.
