02 / 05

Context

What it is

Telegram Sheets Task Bot is a private task workflow where employees receive and change tasks in Telegram while Google Sheets remains the only persistent store. It supports controlled status transitions, task creation, reminders, reports and confirmed interpretation of text or voice.

The problem it solves

A spreadsheet is convenient for the business but does not provide application transactions by itself. Concurrent updates can diverge, a stale callback can apply an obsolete transition, AI can select an unauthorised task, and a delivery error can leave a changed row without a message or audit evidence.

System

Technical stack

Architecture

Apps Script V8 pulls Telegram updates. Every action rechecks telegram_id and domain permissions. A callback carries an HMAC and task/session version; the application layer builds a transaction plan, then Sheets batchUpdate atomically commits the task, audit, idempotency marker, outbox, session and Telegram offset. A separate dispatcher delivers the outbox with bounded retries.

Why this architecture

The design accepts Sheets as a deliberate constraint rather than pretending it is a regular database. A pure TypeScript domain builds the transaction plan before one batch is applied; the offset commits with the effect, so a repeated update is either recognised safely or the whole operation completes together.

04 / 05

Evidence

Strengths

Without a separate server, the system still closes the main operational risks: a signed stale-action guard, atomic multi-range writes, durable outbox, dead-letter after bounded retries, protected columns and budget reservation before an AI call. AI proposes actions only among authorised tasks and never writes without confirmation.

What it proves

The case demonstrates system thinking under strict cost and platform constraints: auth, state machine, integrity, transaction design, AI guardrails, speech integration, operations and traceable QA form one maintainable product.

Quality · QA

How quality was engineered

Coverage-gated Vitest covers auth, permissions, callback integrity, the state machine, transaction plans, outbox, retries, schema migration, AI budget and provider contracts. A 20,000-task snapshot load test, strict TypeScript, ESLint, a reproducible Apps Script build, security scan and CI verification complete the gate.

Honest boundaries

The public case exposes no employees, tasks, sheet content, spreadsheet or Cloud project IDs, Telegram messages, voice, callback payloads, credentials or private source. Polling runs on a minute rhythm and depends on Apps Script quotas; speech and AI use external providers. AI cannot bypass domain permissions or human confirmation.
