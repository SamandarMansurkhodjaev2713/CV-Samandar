02 / 05

Context

What it is

MeetingFlow RU/UZ is a private automation for the complete working-meeting lifecycle. An authorised employee creates a Meet through Telegram, the recording enters speech-to-text, the result becomes a Google Doc and is delivered to a work group with persisted status.

The problem it solves

Calendar, recorder, speech provider, Drive and Telegram are independent systems. A webhook can be delayed, transcription finishes asynchronously, delivery can fail and a repeated callback can trigger the same paid processing twice. Without shared state, nobody can prove where a meeting stopped.

Architecture

A Cloudflare Worker is a narrow signed relay between Telegram and Google Apps Script. Apps Script owns the state machine and persists meetings, callbacks, failures and delivery state in Sheets; Calendar/Meet creates the event, tl;dv provides the recording, ElevenLabs handles RU/UZ and mixed speech, and Drive/Docs stores the result. A polling fallback complements webhooks and every external step uses an idempotency key.

Why this architecture

The main logic stays in the managed Google perimeter without a permanent server, while the Worker isolates the public Telegram edge. Webhooks provide the fast path, polling closes missed events, and replay checks stored state instead of repeating a paid operation.

Evidence

Strengths

The value is end-to-end completion, not transcription alone. MeetingFlow connects permission, calendar event, recorder readiness, diarized RU/UZ text, document and delivery receipt in one observable operational history.

What it proves

The case demonstrates mature integration engineering: multiple asynchronous providers, multilingual speech, serverless constraints, a secrets boundary, idempotency, recovery, operational checks and a handover the owner can actually run.

Quality · QA

How quality was engineered

Automated tests cover relay redirects, request signatures, retries and downstream failure. Apps Script includes unit checks for state transitions and configuration; a separate end-to-end path validates the Telegram relay. Failures and delivery state are logged, with health checks, repair routines and a repeatable handover runbook.

Honest boundaries

The public page exposes no employees, meeting links, audio, transcript, documents, calendar, Drive, group, bot identifier, webhook secrets or production logs. Speech quality depends on recording, language and diarization; recorder access depends on tl;dv and Meet policy, and Apps Script has quotas. Automated summarisation is not claimed: the system stores the full transcript.
