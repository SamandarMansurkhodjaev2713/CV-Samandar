02 / 05

Context

What it is

A Telegram task-automation track: the public Rust Task-manager and a private Task Manage Bot with AI/voice-to-task logic, reminders, assignments and operational workflows.

The problem it solves

Tasks buried in chats, voice notes and quick messages get lost. You need a system that turns unstructured communication into tasks, deadlines, reminders, statuses and follow-through.

03 / 05

System

Technical stack

RustTeloxideSQLxPostgreSQLDockerGitHub Actions

Architecture

A bot layer takes commands and messages, a domain layer owns tasks and statuses, a storage layer holds the data, a scheduler/outbox handles reminders, and retry/idempotency patterns protect the workflow from failures.

Why this architecture

A Telegram bot turns into chaos fast if commands, business logic and the database are mixed. Layer separation keeps the code clear, testable and ready to grow.

Boundaries

Honest boundaries

Voice recognition quality depends on the recording and the language: on noisy audio or a strong dialect I do not guarantee accuracy. The Rust core is public; the private AI/voice layer stays closed. Integrations with third-party trackers (Jira, Asana) are out of the current scope.
