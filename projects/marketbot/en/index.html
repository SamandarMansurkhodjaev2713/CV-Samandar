Context

What it is

A private e-commerce automation platform: offer ingestion, subscriptions, affiliate links, Telegram notifications and an operational panel.

The problem it solves

A commerce/offers product needs ingestion, filtering, subscriptions, notifications, link generation, admin control, error handling and event delivery to the user — without manual routine.

03 / 05

System

Technical stack

PythongRPCRabbitMQPostgreSQLTelegramReact

Architecture

An ingestion service collects and normalizes offers, a subscription service stores user interests, a notification service delivers events, an affiliate/link service generates links, a Telegram bot surfaces value to the user, and an admin panel gives control and diagnostics.

Why this architecture

Commerce automation depends heavily on events and external sources. An event-driven approach over queues makes the system resilient to delays, failures and a growing number of scenarios.

Quality · QA

How quality was engineered

pytest for deduplication, money/discount rules and URL domain logic; service-level checks for retries, retention, requeue and Telegram notifications; plus a documented load-test report. This lowers the risk of duplicate offers, wrong prices and lost notifications.

Boundaries

Honest boundaries

The system depends on external marketplaces: a change to their markup or API breaks collection and requires maintenance — that is a built-in cost of ownership, not a one-off delivery. Price accuracy at the moment of purchase is not guaranteed. Settlement with the platforms and the tax side stay with the business.
